dy3-polaris 多智能体协同边界与闭环链路评审报告

评审范围：协同边界场景（时序/乱序/失联/冲突/兜底/孤岛）、业务硬编码侵入、调用方式统一性、7+2 边界对齐、两条闭环链路；日期：2026-08-07

一、协同边界场景结论（Top 风险）

场景现状缺口严重度
任务冲突（并发写画像）写画像路径 ≥5 条（练习判题/考核/审核/决策/BKT）无锁/无版本/CAS；读-改-写跨调用不原子；编排声明的 asyncio.Lock 从未使用 → 多 agent 并发丢失更新高
失联（无超时）run_agent 同步直调 workerworker 挂起 → 请求永久悬挂；/api/query 无超时上限；计划级超时默认关闭高
协作闭环未打通广播→inbox 订阅已实现inbox 只写不消费，无内部消费者触发 agent 动作；真实协作是 run_guidance 函数直链（与总线无关）→ 消息驱动协作实际未闭环高
消息乱序/线程安全publish 全同步，单事件循环有序无线程锁（多进程即失效）；inbox 无水位/ack/持久化（超 200 条丢最旧，重启即丢）中-高
编排兜底任务超时/重试已实现重试仅 1 次无退避；重试不重置 context；Voting 策略无任务级超时；失败无部分结果返回中
孤岛HandoffManager/DiscoveryService/ReflectionEngine/PersistentKernel 等 12+ 组件完整实现全部仅测试引用，生产 wiring 不实例化；IntegrationBridge 的 process_query_with_profile/feedback_to_profile 未接入端到端中
异常兜底L5 13 端点 _err 覆盖率 ~100%agent_detail 前置逻辑未包 try（可能裸 500 HTML）；-32400 通吃内部错误；无 trace_id 贯穿低-中

三、调用方式与接口统一性

项现状结论
统一门面IntegrationBridge 存在（上下文组装/事件/反馈）但非强制使用半统一：/api/query 直接走 agent worker，不走桥
服务创建unified_app 手工 new 十余服务；SkillExecutor 空依赖占位后注入碎片化组装期打补丁
响应信封REST {code,data,message} / JSON-RPC / Legacy 三种并存；_ok/_err 8 处复制不统一
错误码-32400~-32406 被 L3/L0 cc3/cc_integration 三处复用冲突需注册表收敛
方法命名画像快照三套（get_profile_snapshot/snapshot/get_snapshot）；Agent ID 前缀混合不一致

四、两条闭环链路功能覆盖（端到端断点）

链路环节状态
链路A
学情闭环		学情采集半开：仅答题有入口；浏览/提问/行为无采集通道（EventCollector/UpdatePipeline 未接线）
画像更新可用：练习判题→BKT→写回；ProfileTracingService 全链路休眠
知识诊断可用：run_diagnosis 完整 + 广播薄弱块
策略生成偏弱：决策引擎只生成知识查询计划；path_simulation 技能未暴露
习题推送拉取式：无主动推送机制
行为反馈断裂：feedback_to_profile 调不存在的 record_feedback（空转）；hitl feedback 空响应
链路B
实时协作		多智能体分工可用：4 Agent + 总线 + 前端可视化 + inbox
实时答疑前端断点：后端 /api/query 完整，前端 query 视图是占位符（未接线）
课堂引导缺失：无班级/课堂维度，仅一对一

可端到端走通的最小闭环：练习答题 → BKT → 画像 → weak_kps → 薄弱优先出题 → WS 学情广播。
