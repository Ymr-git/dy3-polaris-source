# 用户画像库（多维测试）

> 用途：按 3 维度（身份 × 能力 × 方向）+ 主动/被动，设计贴合现实的画像，
> 逐个带需求体验系统，发现不足 → 改进 → 再体验，反复迭代。

## 维度定义

- **身份**：学生 / 工作科研员 / 感兴趣的人 / 老师
- **能力**：一无所知 / 略懂一点 / 熟悉 / 掌握
- **方向**：稀土发光材料相关的科研方向与职业
- **态度**：主动（愿探索）/ 被动（不愿摸索，需系统引导）

---

## 画像 1：小白本科生（被动）
- 身份：学生（材料科学与工程 · 大一）
- 能力：一无所知
- 方向：刚入学，尚未分方向
- 背景：被老师布置"用这个系统了解一下发光材料"，完全没基础，不常碰新软件。
- 需求：先想知道"这是干嘛的"，希望一进来就有明确引导；看不懂专业术语。
- 态度：**被动**——不会主动点来点去，需要系统把下一步喂到嘴边。
- 体验目标：能否在无引导下 3 步内明白"我该干嘛"。

## 画像 2：研究生（主动）
- 身份：学生（研究生 · 刚进发光材料课题组）
- 能力：略懂一点
- 方向：Dy³⁺ 白光荧光粉
- 背景：有化学基础，刚进组，导师让先熟悉 Dy³⁺ 发光机理和制备工艺，要准备实验。
- 需求：系统学机理 + 看制备流程 + 做练习自测。
- 态度：**主动**——愿意点遍所有菜单，探索功能。
- 体验目标：能否找到机理讲解、制备实操、分阶练习，形成学习闭环。

## 画像 3：企业科研员（主动）
- 身份：工作科研员（稀土荧光粉研发工程师）
- 能力：熟悉
- 方向：浓度猝灭、能量传递、热稳定性
- 背景：企业研发多年，熟悉材料，但想快速查证具体参数/机理，效率优先。
- 需求：快速查专业问题（如"浓度猝灭机理"），看知识图谱关联，查证数值。
- 态度：**主动**——但要求快，讨厌绕弯。
- 体验目标：能否快速定位知识、图谱、证据，不浪费时间。

## 画像 4：LED 器件工程师（被动）
- 身份：感兴趣的人（照明/LED 器件工程师）
- 能力：略懂一点（懂应用，不懂发光机理）
- 方向：白光 LED 封装、健康照明
- 背景：做器件，知道蓝光危害、显色指数，但不了解稀土发光粉的内部机理，只想从应用角度了解。
- 需求：了解 Dy³⁺ 荧光粉怎么用在白光 LED、怎么降蓝光危害，不想啃理论。
- 态度：**被动**——只想要结论/应用建议，术语太多会放弃。
- 体验目标：能否用应用视角快速得到"怎么做"的答案。

## 画像 5：材料课老师（主动）
- 身份：老师（材料科学课程教师）
- 能力：掌握
- 方向：发光材料教学
- 背景：教材料课程，熟悉发光材料，想用系统辅助备课、出题、找教学资源。
- 需求：出分阶测试题、找讲解素材、看学生画像对比。
- 态度：**主动**——会探索教师/管理功能。
- 体验目标：能否快速生成教学资源、出题、看学生学情。

## 画像 6：跨专业爱好者（被动）
- 身份：感兴趣的人（物理/化学业余爱好者）
- 能力：一无所知
- 方向：只是对"荧光粉为什么发光"好奇
- 背景：完全没专业背景，被短视频吸引来，只想弄懂"发光是怎么回事"。
- 需求：通俗的、生活化的解释，不要专业术语堆砌。
- 态度：**被动**——系统不主动解释就会流失。
- 体验目标：能否用大白话让他看懂"发光机理"。

## 画像 7：在读博士生（主动）
- 身份：学生（博士生 · 上转换发光方向）
- 能力：熟悉
- 方向：上转换纳米材料、生物成像
- 背景：研究上转换材料，需要查前沿、看能级结构、能量传递路径。
- 需求：深度机理 + 图谱关联 + 能级跃迁可视化。
- 态度：**主动**——会深挖细节。
- 体验目标：能否满足深度查询与可视化需求。

## 画像 8：实验室技术员（被动）
- 身份：工作科研员（实验室表征测试员）
- 能力：略懂一点
- 方向：XRD / PL 表征操作
- 背景：负责操作仪器，懂"怎么做"不懂"为什么"，要按规程操作。
- 需求：实操步骤、参数、注意事项，不要理论。
- 态度：**被动**——只想要清晰的步骤清单。
- 体验目标：能否快速找到实操指南和参数。

2. 【数据质量·严重·待解决】检索不相关：问「Dy3+ 浓度猝灭」检索到 Bi3+/Nd/Ce3+/Eu3+ 内容；问「Dy3+ 能级跃迁」检索到 Ce3+/Eu3+ 跃迁。根因：知识库 PDF 转文本时离子符号（`<sub>/<sup>`）丢失 → `_extract_ions` 提取不到文档离子 → 实体一致性门失效，检索本身也匹配到错离子。
3. 【数据质量·严重·待解决】答案大量空词：化学式/数值丢失（" 离子"、" 荧光粉"、"8 m"应为 8μm、"430nm"），PDF 转文本上下标丢失，靠 LLM 缓解（当前未配 key 无法缓解）。
4. 【已修复】通俗度失效：画像 1 小白问「发光材料是什么？用大白话讲讲」，答案曾是学术术语堆砌 → 新增内置通俗讲解库 `_PLAIN_LANGUAGE_GUIDES`（8 个核心概念的大白话解释 + 生活化比喻），检测「大白话/通俗/说人话」等请求词直接返回通俗讲解，不罗列证据句。复测：发光材料/荧光粉/稀土/上转换 4 问均返回通俗比喻讲解。
5. 【缺口确认】职业方向推荐：画像 9 问「毕业能去什么岗位/补什么技能」，答案跑题到"稀土发光应用前景"，无职业推荐能力。
6. 【环境】旧后端实例用系统 Python 3.14 启动且知识库未加载（health `entities=0` 为探针写死值，非真实状态），已改用 `.venv` 正确启动（实体 21405）。

本轮结论：role 映射、通俗化已修复；检索不相关与空词为深层数据质量问题（PDF 上下标丢失），需数据侧治理或 LLM 缓解；职业推荐为后续改进项。

31. 【研究·可借鉴方法】检索了 2025–2026 agentic RAG / 检索循环 / 答案质量 / 学习者建模的文献与案例，结论映射到本项目待修项：
   - **检索相关性（答非所问根因）**：hybrid(密集+BM25)+RRF(k=60)+cross-encoder rerank 是生产共识，rerank 是单点提升最大的一环（MRR +0.07~+16%、检索失败 -67%）；候选集先拉 30–100 再 rerank，top-k~20，最强块放头尾（lost-in-the-middle）；query 侧加 HyDE/step-back/子问题改写（MQR-A1 蒸馏意图、LiveRAG 多面改写）。→ 本项目已有 hybrid + 离子一致性门，缺 rerank 与 query 改写，是治「答非所问」的首要抓手。
   - **拒答治理（过度拒答根因）**：CRAG「检索评估器」输出 correct/ambiguous/incorrect 三态再决定继续/补充/回退，替代二元拒答；Self-RAG 用 critic 判断「是否需检索/证据是否支持」；领域门应放宽为「有检索命中即尝试作答 + 证据不足才诚实说明」，而非「术语不命中即拒答」。
   - **答案可信度**：Debate-Augmented RAG(DRAG) 非对称信息辩论（正方见文档/反方只见问题）已在本项目 `_run_candidate_debate` 实现；补 RAGAS faithfulness/context-precision 自动评测 + golden-set 回归（Recall@K/MRR/nDCG）。
   - **通俗化/画像自适应**：YourQA(AAAI2006)、US10366332、PersonaRAG 的共同点是显式 learner model（阅读水平/学习风格/粒度/可视化偏好）+ 按档位定制答案粒度风格；应把「大白话关键词触发」升级为「按 learner 档位（beginner/θ<阈值）自动通俗化」。
   来源：[hybrid-rag](https://github.com/sahandmsh/hybrid-rag)、[CRAG](https://www.kore.ai/blog/corrective-rag-crag)、[DynamicRAG](https://api.scienceopen.com/document/read?vid=c9a0861d-4e95-49fb-8f32-b3ac9c8df81f)、[Debate-Augmented RAG](https://aclanthology.org/2025.acl-long.770/)、[Self-Reflective Debate](https://huggingface.co/papers/2506.06020)、[GaRAGe](https://aclanthology.org/2025.findings-acl.875/)、[YourQA](https://aaai.org/papers/flairs-2006-153/)、[PersonaRAG](https://ceur-ws.org/Vol-3784/paper1.pdf)。
